# プライズポストメーカー

ゲームセンター向けに、Xへの投稿文章をローカルで作るWindows 10/11 x64用アプリです。Tauri 2、HTML/CSS/TypeScript、JSON保存を使用します。X API・OpenAI API・有料APIは使いません。

**投稿するのは担当者です。** 自動ログイン・自動投稿はしません。APIキーやログイン情報を入力・保存する機能もありません。

## はじめて使う方へ

1. このリポジトリの **Actions → Windows portable EXE** を開き、成功した実行の **Artifacts → PrizePostMaker-windows-x64** をダウンロードします。GitHubへのログインが必要な場合があります。
2. ダウンロードしたArtifactsのZIPを展開し、中の `PrizePostMaker-windows-x64.zip` も展開します。
3. `prize-post-maker.exe` を起動します。アプリのインストールは不要です。ただし **Microsoft Edge WebView2 Runtime** が必要です。起動できない場合はMicrosoft公式サイトからEvergreen Runtimeを導入してください。署名なしEXEのためSmartScreenで確認される場合があります。
4. 中央の「商品マスター（登録・編集・CSV）」を開き、商品名、作品名、キャラクター名、メーカー名、確認済み入荷日を登録します。商品名以外は空欄でも使えます。未確認の日付は入力しないでください。
5. 左のメニューで「月間入荷予定」「当日の入荷・稼働」「完売のお知らせ」「入荷遅延」を選び、商品にチェックします。複数選択できます。月間本文には商品一覧を出さず、右側の「入荷予定表の月」で案内する月を選びます。登録商品一覧の月絞り込みは別の機能です。
6. 月間は月、当日の入荷情報は日付を指定します。完売・入荷遅延はタイトル・テンプレートを選べます。商品の状態は一覧または右側で手動指定します。遅延後の日程など、登録項目にない確認済み情報は備考に記入します。空欄情報は自動で創作しません。
7. 右のプレビューを確認します。作品・キャラクター・メーカーからタグを作ります。タグは編集できます。右側の最終文章も直接編集できます。設定から再生成すると手動編集は置き換わります。
8. 必要なら画像を選びます。JPEG/PNG/GIF/WebP、最大4枚、1枚5MB以下。GIFは1枚のみです。元ファイル名とプレビューを確認します。画像は今回の起動中だけ保持されます。
9. 文章・商品・日付・画像を確認し、「担当者が確認しました」にチェックします。「文章をコピー」または「Xの投稿画面へ移動」を使用します。文章や画像を変更すると確認チェックは解除されます。
10. **X画面で画像の元ファイルを手動添付し、再確認して投稿してください。** intent画面へ画像は渡せません。コピーを使った場合は文章を貼り付けてください。Xへのログインは通常の外部ブラウザで行います。

文字数は通常投稿の重み付き280文字に対応します。日本語は原則2、URLは23、絵文字の一部はまとまりで数えます。空欄・不正な文字・文字数超過ではコピーとX画面への移動を無効にします。X側の最終確認も行ってください。

## Excel入荷予定表を使う

対象は `入替指示書_マクロ版(3).xlsm` などの **.xlsm / .xlsx** ファイルです。

1. 左側の「Excel入荷予定表を読み込む」を開きます。「Excelファイルを選択」、またはファイルのドラッグ＆ドロップで読み込みます。EXEではウィンドウへのドロップにも対応します。
2. 「縦」シートを自動で探します。1行目に `稼働予定日` `品名` `入数` `CS数` `メーカー` が必要です。通常はA〜E列ですが、列名から判定するため順番が変わっていても使えます。ヘッダーの前後空白・全角英字も正規化します。
3. 「単日カレンダー」で日を選ぶと、その稼働予定日の商品をすべて表示します。「開始日」「終了日」と「期間で検索」も使えます。範囲の両端を含みます。「すべての日付を表示」で元に戻せます。商品名（正式名または投稿名）・メーカーでも絞り込めます。
4. 商品のチェック、表示商品の全選択、解除ができます。初期状態は全件チェックOFFです。日付や検索条件を変えるとチェックをすべて解除します。0件・未選択では追加ボタンを押せません。
5. 商品表の「投稿名を編集」を開くと、投稿用の商品名を短く編集できます。元の品名は別に保持します。「商品状態」は **予定・入荷済み・稼働中・準備中・完売・入荷遅延** から担当者が変更します。入数・CS数も内部データと一覧に保持します。
6. 「選択した商品を追加」で、**チェックした商品だけ**をマスターと右側の投稿追加済み一覧へ追加します。未選択商品は投稿へ追加しません。追加後は検索チェックを解除します。右の一覧で個別削除・上へ／下へ並べ替えができ、文章もその順序に変わります。追加済みの商品を再選択しても重複しません。投稿から削除してもマスターは残ります。メーカーからタグを作り、既存のタイトル候補・テンプレート・文章編集を利用できます。
7. **稼働予定日は実際の稼働確定日ではありません。** 投稿の商品行には予定日やメーカーを挿入しませんが、一覧・内部データには保持します。Excelから取り込んだだけで「稼働中」にはしません。完売・遅延の投稿種類では商品の状態も一致させてください。状態が矛盾する場合は文章生成を止めます。

Excel日付セル、1900／1904方式のシリアル値、`YYYY-MM-DD` / `YYYY/MM/DD` の文字列を扱います。品名・日付は必須、メーカーと数量のセルは空欄でもかまいません（列は必要です）。数値は0以上の整数です。空行は無視します。不正行があれば行番号を表示し、取込全体を中止して以前のデータを守ります。上限は20MB・10000商品行、ZIP展開合計100MBです。パスワード付きExcelには対応しません。

読み込みはローカルだけで行い、元ファイルを変更しません。VBAマクロ・数式は実行せず、外部リンクも更新しません。数式の保存済み値が無い場合は、Excel側で再計算して保存したファイルを使ってください。Excelファイル自体を外部へ送信する処理はありません。担当者がX画面への移動を選んだ場合だけ、確認した投稿文章をXの投稿画面へ渡します。

**再読み込みと重複について:** 同じ「稼働予定日・元の品名・メーカー・元の行番号」は1商品として扱います。同じ名前でも別日・別行なら区別します。元の行番号は一覧にも表示します。ファイル名を変えて読み込んでも重複せず、数量を更新し、編集した投稿用商品名・状態・作品などを保持します。元表に行を挿入・並べ替えした場合や、予定日・元の品名・メーカーが変わった場合は別商品になります。前のマスターから自動削除はしないため、予定変更時は旧商品も確認してください。

EXEでは元ファイルのパス・名前と読込一覧をJSONへ記憶します。次回起動後に「元ファイルを再読み込み」を押すと同じファイルを読み直せます。起動だけでは無断で再読み込みしません。ファイルを移動・削除した場合は再選択してください。ブラウザ開発モードでは名前だけを記憶し、再読み込み時はファイルを選び直します。Excelバイナリは保存しません。CSV出力は従来の商品5項目のみです。Excelの数量・予定日・状態・登録タグなどの完全なバックアップにはJSONを使用してください。

詳細な設計と変更対象は [docs/EXCEL.md](docs/EXCEL.md) を参照してください。

## コンパクトUIとWindowsの表示サイズ

通知は画面下部の専用領域に表示し、ボタンへ重ねません。左右パネル・商品一覧は独立してスクロールできます。小型画面では中央と右の領域を上下に配置し、それぞれスクロールします。通常の余白・入力欄を縮小し、チェックボックスは18pxを維持しています。

Excelの商品一覧は表形式です。「列幅を調整」で商品名・メーカー・予定日・状態の幅をスライダー（キーボード操作可）で変更できます。横幅が足りない場合は表の中で横スクロールします。商品マスター・登録商品選択・テンプレートの詳細は必要に応じて展開してください。最小サイズは640×480論理ピクセルです。起動時はモニターの作業領域とDPIを参照し、初期サイズを収まる範囲へ調整します。

## 固定テンプレートとツリー投稿

月間入荷予定は商品を選ばなくても、選択した1月〜12月の月で次の文章を生成します。商品一覧・タグ・備考は自動挿入しません。

```text
✨万代書店長野店プライズコーナー✨11月入荷予定表✨

雑貨やぬいぐるみなど記載に無く入荷する景品や、後日入荷予定日が変更になる景品がある場合がございます。
```

当日の入荷・稼働ではカレンダーで選んだ日付から、年を表示しない1投稿目を生成します。

```text
🆕万代書店長野店プライズ入荷情報🆕

11月6日の入荷のお知らせです！詳細はツリーにて⬇️
```

商品紹介は2投稿目以降へ分けます。正式名称をそのまま使い、担当者が投稿用名を編集した場合だけ短縮名を使用します。品名中の改行は表示時だけ空白へ変え、1商品を1行で出します。元のExcelは変更しません。

```text
・クロミ [PtZ]fuwa&hugブランケット / 稼働中です。
```

状態別に「入荷しました。」「準備中です。」「完売しました。」「入荷が遅れています。」を出力します。初期の「予定」や未指定の商品は「予定です（状態未確認）。」とし、稼働予定日から実際の状態を推測しません。旧データの「遅延」は読込時に「入荷遅延」として扱います。

商品行を途中で切らず、Xの重み付き280文字以内に自動でまとめます。1商品だけで超過する場合は警告して生成を止めます。自動で省略・切り詰めはしないので、必要なら担当者が投稿名を編集してください。ハッシュタグは日別の商品紹介に限り、チェックで任意に末尾へ付けられます。

右側の「投稿ごとの確認・コピー」で各文章の表示・編集・確認・個別コピー・Xを開く・上／下への順序変更ができます。文章・画像・順番を変えると確認が解除されます。設定変更による再生成では投稿順序も生成順へ戻ります。X側では最初の案内を投稿し、後続の商品紹介を担当者が手動で返信してください。自動投稿・自動返信はしません。画像も手動添付です。

## テンプレートと履歴

- 完売・入荷遅延向けに標準とコンパクトのテンプレートを同梱しています。月間・日別案内は指定の固定文を使用します。本文を編集し、名前を付けて新規保存・上書き保存・削除できます。
- 変数は `{title}` `{date}` `{products}` `{note}` `{hashtags}` `{count}`（選択商品数）です。
- 「作成履歴に保存」で現在表示している1投稿の文章を保存できます。直近200件を保持し、再利用・削除ができます。**履歴は投稿済みを意味しません。** コピーやX画面への移動だけでは履歴は保存しません。
- 商品は編集・削除でき、作品名・キャラクター・メーカー・登録ハッシュタグ（空白区切り）を設定できます。Excelの正式名称を変えずに投稿用名を編集できます。テーマはヘッダーのボタンでOS設定・ダーク・ライトを切り替えます。

## CSV入出力

商品マスターからUTF-8のCSVをインポート／エクスポートできます。最初に空のマスターをエクスポートするとヘッダーの見本を作れます。

```csv
name,work,character,maker,arrivalDate
```

`name` は必須、他は空欄可。日付は `2026-11-05` のような実在する `YYYY-MM-DD` 形式です。日付は記入例であり入荷情報ではありません。各項目は200文字以内です。カンマ・引用符・改行はCSVの引用規則で扱います。BOM付きUTF-8に対応しています。

インポートは追加方式です。同じCSVを繰り返すと重複します。1行でもエラーがある場合は全体を取り込みません。上限は5MB・10000行です。表計算ソフトの数式実行を避けるため、エクスポート時に `=` `+` `-` `@` などで始まる値には先頭にアポストロフィを付けます。再インポート時もこの保護文字は残ります。

## 保存場所とバックアップ

Windowsの `%APPDATA%\jp.naganoprize.prizepostmaker\data.json` に商品・テンプレート・履歴・テーマ・Excel読込元と一覧を保存します。**EXEはポータブルですが、データはEXEと同じフォルダーには保存しません。** 別PCへ移すときはアプリを終了し、このフォルダーをバックアップ・移行してください。保存前のデータを `data.json.bak` に残します。画像は保存しません。

読み込みエラー時は上書き保護のため編集を停止します。アプリを終了し、まずフォルダー全体を退避してください。必要なら破損した `data.json` を別名で保管し、正常な `data.json.bak` のコピーを `data.json` にして再起動します。バックアップも不正なら商品CSVなどから復元してください。複数ウィンドウ／プロセスで同時編集しないでください。

ブラウザ開発モードでは、そのブラウザのlocalStorageを使います。デスクトップアプリのJSONとは別で、ブラウザデータ削除により消えます。

## 開発する方へ

設計とファイル構成は [docs/DESIGN.md](docs/DESIGN.md) を参照してください。

### Windowsで開発・ビルド

必要なもの:

- Windows 10/11 x64
- Node.js 22 LTSとnpm
- Rust stable（MSVC、rustup公式インストーラー）
- Visual Studio 2022 Build Toolsの「C++によるデスクトップ開発」とWindows SDK
- Microsoft Edge WebView2 Runtime

リポジトリを取得し、PowerShellでフォルダーに移動して実行します。

```powershell
npm ci
npm test
npm run build
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run tauri dev
```

終了するには起動したターミナルでCtrl+Cを押します。ブラウザだけでUI開発する場合は `npm run dev` を使います。

ポータブルEXEのリリースビルド:

```powershell
rustup target add x86_64-pc-windows-msvc
npm run tauri build -- --no-bundle --target x86_64-pc-windows-msvc -- --locked
```

出力は `src-tauri/target/x86_64-pc-windows-msvc/release/prize-post-maker.exe` です。インストーラーやAPIキーは不要です。

### 自動テスト

```powershell
npm test
npx playwright install chromium
npm run test:e2e
npm run format:check
```

単体／UIテストはCSV、日付、生成、タグ、X文字数、保存データ検証、Xへの引き渡し、画像制約、確認解除を対象にします。Playwrightは実ブラウザで商品登録・生成・履歴復元・文字数制限・破損保護を確認します。システムのChromiumを使う場合は環境変数 `CHROMIUM_PATH` で実行ファイルを指定できます。

Rustの保存テストは `cargo test --locked --manifest-path src-tauri/Cargo.toml` でJSON保存、バックアップ、破損保護を検証します。LinuxでTauriをビルドする場合は別途WebKitGTK 4.1、GTK 3などの公式前提パッケージが必要です。

### GitHub Actions

[Windowsビルド定義](.github/workflows/windows.yml) は `windows-latest` を使用します。`main` / `work` / `feat/**` へのpush、`v*` タグ、pull request、手動実行で動作します。npmのロックファイルで依存を導入し、単体・ブラウザ・Rustテスト後にWindows x64 EXEをビルドし、READMEとともにZIPでArtifactsへ保存します（保持30日）。リリースへの自動公開は行いません。

手動実行はGitHubの **Actions → Windows portable EXE → Run workflow** から行います。初回はActionsの有効化が必要な場合があります。

### 現時点の検証範囲

LinuxクラウドでTypeScript型検査・本番フロントエンドビルド、単体/UIテスト38件、Chromium E2E 14件、独立ハーネスから本番Rust保存・Excel読取モジュールのテスト2件を実行済みです。Tauri設定はCLI同梱のスキーマで検証しています。Excelは指定の列構成の生成フィクスチャ（マクロ有効形式、列順変更、保存済み数式値、日付方式など）で検証済みです。添付された `入替指示書_マクロ版.xlsm` でも135件の読込、2026-11-05の8件抽出、チェックした1件のみの追加、元ファイルのハッシュ不変を確認しました。添付ファイル自体はリポジトリに保存していません。ローカルで実ファイル検証を再実行する場合は、環境変数 `EXCEL_FIXTURE_PATH` にそのパスを指定してテストしてください。未指定の場合は添付ファイル専用の単体テスト1件・E2E 1件をスキップし、生成フィクスチャのテストは実行します。

Windows x64ビルドの成否とArtifactsは対象コミットのActions実行結果を参照してください。旧版のEXE動作確認は利用者から報告されています。このUI改修版のWindows実機での125％／150％表示、初期ウィンドウサイズ調整・ネイティブコピー・X画面・再読込は別途確認が必要です。ブラウザでは1920×1080、1536×864/DPR1.25、1280×720/DPR1.5、910×512/DPR1.5、640×480とリサイズを検証します。これらはWindows実機DPI検証そのものではありません。
