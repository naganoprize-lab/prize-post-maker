# Excel入荷予定表連携 設計

既存のTauri 2 / TypeScript / JSON保存構成に追加する。対象は `入替指示書_マクロ版(3).xlsm` を含む .xlsm / .xlsx。実ファイルは未提供のため指定形式の生成フィクスチャで検証する。

## 変更対象

- `src/excel.ts`: ExcelJSを使用した読み取り専用解析、ZIP展開サイズ制限、ヘッダー検証、日付変換、範囲抽出、重複マージ
- `src/excel-ui.ts`: 選択・ドラッグ＆ドロップ、カレンダー／範囲検索、個別・全選択・解除、一括投稿追加、状態・投稿名編集、記憶したファイル再読込
- `src/domain.ts`: 商品の任意追加属性と旧JSONとの互換検証、商品状態を反映した生成
- `src/main.ts`: Excel画面マウント、既存マスター編集で追加属性を保持、商品選択へ接続
- `src-tauri/src/excel.rs` / `lib.rs`: ローカルファイル読取と拡張子・サイズ検証
- `src-tauri/Cargo.toml` / capabilities: ネイティブファイル選択ダイアログ
- tests / e2e / README: 自動検証と操作方法

## 入力

「縦」シートを自動取得する。1行目のヘッダー「稼働予定日」「品名」「入数」「CS数」「メーカー」をNFKC正規化・前後空白除去して列番号を割り当てる。列順変更を許容し、欠落・同名重複をエラーとする。完全空行は無視し、データ行に不備があれば行番号付きで全体を拒否し、既存商品を変更しない。ファイル20MB、ZIP展開合計100MB、最大10000商品に制限する。

ExcelJSはOOXML ZIPを読むだけで、VBA、数式、外部リンクを実行・更新しない。数式セルは保存済みresultだけを使い、値が無い場合は再計算済みファイルの保存を案内する。Excelの1900／1904日付システム、日付セル、シリアル値、YYYY-MM-DD / YYYY/MM/DD文字列を扱う。UTCの年月日で日付を保持しタイムゾーンによる前日化を防ぐ。存在しない日付は拒否する。

## 商品と重複

投稿用nameと元のoriginalNameを別に保持し、scheduledDate・units・cs・status・sourceKeyを任意属性として既存Productへ追加する。既存JSONはそのまま読める。稼働予定日をarrivalDateへコピーしない。初期状態は「予定」。状態は「予定」「入荷済み」「稼働中」「完売」「遅延」で担当者が変更する。

sourceKeyは [予定日, 元の品名, メーカー] のJSON文字列。同内容の行はまとめる。同じキーで数量の異なる複数行は曖昧なため拒否する。再読込では数量を更新し、投稿用name・状態・作品・キャラクターを保持する。予定日・品名・メーカーが変わった行は別商品とする（不確かな同一性を推測しない）。旧商品の自動削除はしない。ファイル名をキーに含めないためコピー／別名ファイルの再取込でも重複しない。

## 画面と保存

Excelパネルには単日のdateカレンダーと開始／終了の期間検索を設ける。全商品は取込済み一覧で保持、表示された商品を選択して既存投稿画面へ一括追加（マスターをupsertしてそのIDを選択）する。0件は日本語表示する。絞込変更でチェックを解除し、非表示商品の意図しない追加を防ぐ。

ネイティブではダイアログとTauriのファイルドロップイベントからパスを取得する。アプリJSONに元ファイル名とパスを保存し、次回の「元ファイルを再読み込み」で同じファイルを読む。起動時の無断読取・変更はしない。ブラウザ開発では安全なファイルパス取得ができないので名前だけ記憶し再選択を案内する。ExcelバイナリをJSONへ保存しない。元ファイルが移動・削除された場合はエラーと再選択を案内する。

生成はExcel商品の個別状態を使い、予定商品は「稼働予定（日付）・未確定」と明示する。完売・遅延投稿で対象商品の状態が矛盾する場合は生成を拒否し状態変更を案内する。メーカーのタグ、既存タイトル・テンプレートへ連携する。入数とCS数は内部・一覧で保持し、未指定で投稿には自動挿入しない。
