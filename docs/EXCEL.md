# Excel商品選択連携の設計と変更対象

Tauri 2 / TypeScript / JSON保存を維持する。既存の4投稿種類、商品マスター、CSV、タイトル、テンプレート、タグ、履歴、X連携は維持する。

## 変更対象

- `src/excel.ts`: 読み取り専用Excel解析、ZIPサイズ制限、ヘッダー、日付、検索、再取込マージ
- `src/excel-ui.ts`: ファイル選択／ドロップ、単日・期間・商品名・メーカー検索、初期OFFのチェック、一括追加
- `src/selection.ts`: 表示中かつチェック済み商品の抽出、重複追加防止、順序変更
- `src/domain.ts`: 元行番号・正式名称・予定日・数量・状態、登録タグ、商品数変数
- `src/main.ts` / `style.css`: 左の読込・検索、中央の抽出結果、右の追加済み商品・既存投稿設定・プレビュー
- `src-tauri/src/excel.rs` / `lib.rs`: 拡張子・サイズ検証付きローカル読取
- `src-tauri/Cargo.toml` / capabilities: ネイティブ選択ダイアログ
- tests / e2e / README: 自動検証と操作方法

## 実ファイルと入力構造

添付 `入替指示書_マクロ版.xlsm` を読み取り専用で確認。「縦」シートには1行目に `稼働予定日` `品名` `入数` `CS数` `メーカー` があり、有効商品135件。2026-11-05の予定は8件。添付バイナリはリポジトリへ保存しない。

ヘッダーをNFKC正規化・前後空白除去して列番号を割り当てる。列順変更を許容し、欠落・同名重複をエラーとする。完全空行は無視する。日付未入力や不正な商品・数量は行番号付きエラーで全体を拒否し、既存データを変更しない。未確認情報を推測しない。上限はファイル20MB、ZIP展開合計100MB、10000商品行。ZIP64・分割・暗号化は非対応。

ExcelJSはOOXML ZIPの保存済み値を読み、VBA・数式・外部リンクを実行／更新しない。数式キャッシュがなければExcelでの再計算・保存を案内する。1900／1904日付方式、日付セル、シリアル値、YYYY-MM-DD / YYYY/MM/DD文字列に対応。UTCの年月日を使い前日化を防ぐ。存在しない日付は拒否する。

## 識別・状態・永続化

正式名称originalNameと投稿用nameを別に保持し、scheduledDate・units・cs・status・rowNumberを保存。元ファイルを書き換えず、予定日を確認済み入荷日arrivalDateにコピーしない。初期状態は「予定」。担当者が「入荷済み」「稼働中」「完売」「遅延」を指定する。完売・遅延投稿で状態が矛盾する場合は文章生成を拒否する。

キーは [予定日, 元品名, 元メーカー, 元行番号]。同名同日の別行を区別する。同じ行の再取込では数量を更新し、編集した投稿名・状態・作品・登録タグ・IDを保持する。ファイル名はキーに含めず、別名コピーでの重複を防ぐ。行の挿入・並替え・予定日などの変更でキーが変わった場合は別レコードとする。旧商品を自動削除しない。行番号がない旧JSONも読め、再取込時は一致する最初の1行に編集情報を移行する。

JSONへ元ファイル名・パス・読込一覧を保存する。起動だけで無断読取せず「元ファイルを再読み込み」で再利用する。ブラウザ開発ではパス取得ができないため名前だけ記憶し、再選択を案内する。移動・削除・読取権限不足は日本語エラー。ExcelバイナリをJSONへ保存しない。

## 選択の不変条件（最優先）

検索チェックと投稿の追加済み一覧を独立して管理する。

- 初期状態・取込後は全チェックOFF。
- 単日／期間／商品名／メーカー変更で検索チェックを解除。
- 表示順は元行番号順。検索は1日／両端を含む期間、正式名または投稿名、メーカーに対応。
- 追加対象は「表示中 AND チェック済み」の集合だけ。非表示・未選択商品は新規追加しない。
- 0件、未選択、読込／保存中は追加ボタンを無効化。選択数は即時表示。
- 追加操作後はチェック解除。追加済み商品は重複なく追記し、暗黙には削除しない。
- 右の一覧で投稿から個別削除、上／下へ並べ替え。文章とタグはこの順序・集合だけから生成。
- マスター登録と投稿への選択は別。投稿から削除しても商品情報は残り、明示的に再選択できる。

選択商品数はテンプレート変数 `{count}` でも使用できる。作品・メーカー・キャラクター・登録タグからタグを生成する。数量は一覧と内部データで保持する。

## 安全性と検証

読込処理はローカルだけで完結し外部送信しない。Xへ渡すのは担当者が最終確認して移動を選んだ投稿文のみ。自動ログイン・投稿はしない。

生成フィクスチャで列順変更、日付方式、数式キャッシュ、不正ファイル、別行識別、再読込を検証。実ブラウザで初期OFF、複数・個別チェック、未選択除外、日付変更解除、重複、削除、順序、既存生成への連携を検証。実添付の検証はEXCEL_FIXTURE_PATHを指定して再実行できる。ファイルはCIへ持ち込まないため、その検証だけは未指定時スキップする。

Windows EXEは既存のwindows-latest CIで、テスト後にTauriビルドし、EXEとREADMEをZIP Artifactsへ保存する。LinuxクラウドでのWindowsビルド・実機実行は未検証。
